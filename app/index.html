Set up Muse Gadget TV

This TV becomes a Muse gadget: Muse can show messages and briefings on it, read and set its volume, and open apps on it. Nothing works until the TV is paired with your Muse account — there is no demo mode and no fake “paired” state.

1 · SDK token

Every gadget needs an SDK token from gadgets.muse.ai (Account → SDK tokens). It starts with mgst_. Muse records the token when the device pairs; it is also sent when the device token rotates.

2 · This TV

3 · Log in over the web

A gadget’s login lives on the web: sessions and token rotation run over HTTPS against the Muse device API. Bluetooth is used exactly once — by the Muse app, to hand a gadget its device credentials — and a completed pairing is just two small files, so whichever gadget client ran that step can hand the result over. That is how the community PSP port logs in with no Bluetooth at all, and it is what happens here. (A Tizen web app cannot advertise a Bluetooth service, so the Muse app cannot provision this TV directly — the full explanation is in the project’s PROTOCOL.md.)

First pair the Muse Gadget SDK’s Linux client with the Muse app on a computer or Raspberry Pi with Bluetooth — the README walks through it — and leave that client off afterwards: only one device can use a pairing at a time, and every token rotation replaces the pair. Then bring the pairing here, easiest first:

Recommended: fetch from the pairing helper

  1. On the computer or Pi where you paired, run the pairing helper from this project’s repo: python3 tools/pairing-helper/pairing-helper.py
  2. It prints a helper address and a 6-digit code. Type both below and press Fetch & log in.
  3. The helper sends the pairing once, only to the request with that code, and then stops. Run it once, at the TV, on a home network you trust.

Whichever way the pairing arrives, the TV checks the credentials against the Muse device API before saving anything — the same check the SDK runs — adopts the pairing’s identity, and from then on connects and rotates its tokens by itself over HTTPS.

Or: paste the two pairing files

Copy identity.json and pairing.json from the pairing client’s state folder (/var/lib/musegadget) and paste both files below. Same check, same result — just more typing on a TV remote.

Last resort: paste the two device tokens

The same credentials as two fields, without the files. With this path the TV keeps its own identity (card 2) — but a pairing’s tokens belong to the identity they were issued to, and the TV presents that identity’s node id when it registers and rotates tokens, so prefer the file login above whenever you have the files.

4 · Voice

The TV can read messages and briefings aloud (text-to-speech via the Tizen web runtime’s speech synthesis — no cloud involved). Muse can also ask for speech per message; this switch controls whether messages are read aloud automatically.

Typing with a remote is slow: a Bluetooth keyboard paired with the TV (Settings → General → External Device Manager → Input Device Manager → Add Bluetooth Keyboard) works in every field here, and in the message box on the main screen.

Read the Gadget SDK Terms at gadgets.muse.ai/sdk-terms before use. Community gadgets pair without manufacturer verification — set up on a network you trust.
